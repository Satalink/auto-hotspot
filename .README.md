# Auto Hotspot

Version: v0.1 concept beta

This project keeps a laptop on the best available network tier by switching between a phone hotspot and fallback Wi‑Fi networks.

## Beta status

This is a concept beta release. The automation is functional as a proof of concept, but it is still being tuned for real-world network transitions and edge cases.

## What it does

When the laptop is connected to a phone hotspot, the script periodically checks whether that hotspot is still available. If it drops out, the script:

- tests the configured hotspot SSID
- switches to a saved fallback Wi‑Fi profile if available
- restores the hotspot when it becomes available again
- keeps the laptop connected to the strongest viable network tier

The implementation is centered on the network-tier manager in [.inc/Manage-WifiTiers.ps1](.inc/Manage-WifiTiers.ps1).

## Why a phone hotspot is useful

A phone hotspot is often the best option when you are traveling, camping, or working in public spaces because it creates a private, device-specific network instead of exposing the laptop directly to a public guest network.

This matters in places such as hotels, restaurants, campgrounds, and other open Wi‑Fi locations:

- the public network is often shared and less trustworthy
- the phone hotspot gives the laptop its own private path to the internet
- the laptop is not directly exposed to the broader public guest network
- the hotspot can be used even when the phone is already connected to a public network, without forcing the laptop to join that public network directly

In other words, the laptop can stay on a private network created by the phone while the phone itself maintains a separate connection to the public network. That allows internet access to continue without exposing the laptop to the open network and without the laptop needing to join that public network as a peer.

This is especially useful for remote work, security-conscious browsing, and avoiding the risk of directly bridging a laptop onto an untrusted public guest network.

## Data usage note

Using a phone hotspot does not consume hotspot data from the phone if the phone itself is already connected to a public network such as a hotel, restaurant, campground, or other open Wi‑Fi. The phone is simply acting as a private router for the laptop, while the phone's internet connection remains the public network connection it already has. In practice, the laptop is using the phone's local network path, not necessarily the phone's cellular data plan, as long as the phone has its own upstream internet access through the public network.

This setup gives you a private, controlled connection for the laptop while keeping the laptop off the public guest network entirely.

## SSID strategy

A practical pattern is to create the same hotspot SSID on both the phone and the laptop so that devices see a single familiar network name, then automatically reconnect to whichever instance is active. In other words, a phone hotspot and a laptop-hosted hotspot can share the same SSID, which makes clients treat them as one network and simply move to the live one when available.

This is helpful for roaming setups where the phone may be connected to a public hotel or campground Wi‑Fi while the laptop needs a private network path, or where a laptop-hosted hotspot can take over when the phone hotspot is unavailable. The result is a smoother experience because devices do not need to manually switch networks—they simply see the known SSID and reconnect to the active source.

## Files

- [auto-hotspot.ps1](auto-hotspot.ps1) — main looping script that loads configuration and runs the tier manager
- [settings.yaml](settings.yaml) — runtime configuration used by the main script
- [.inc/Manage-WifiTiers.ps1](.inc/Manage-WifiTiers.ps1) — Wi‑Fi detection, connection, and hotspot logic
- [.test/test-wifi-scan.ps1](.test/test-wifi-scan.ps1) — standalone Wi‑Fi scan/debug script for testing adapters and SSIDs

## Configuration

Edit [settings.yaml](settings.yaml) to change:

- `PhoneHotspotSsid`
- `FallbackSsids`
- `WifiInterfaceAlias`
- `PollSeconds`
- `PhoneUnavailableThreshold`
- `PhoneProbeMinutes`

Example:

```yaml
PhoneHotspotSsid: "Satalink"
FallbackSsids:
  - "Twin Lakes 3 5G"
  - "Twin Lakes 3"
WifiInterfaceAlias: "Wi-Fi"
PollSeconds: 30
PhoneUnavailableThreshold: 3
PhoneProbeMinutes: 3
```

## How to use it

1. Open PowerShell as Administrator.
2. Ensure the Wi‑Fi profiles for your hotspot and fallback networks are already saved on the machine.
3. Edit [settings.yaml](settings.yaml) with your correct SSIDs and timings.
4. Run:

```powershell
powershell -ExecutionPolicy Bypass -File .\auto-hotspot.ps1
```

The script will continue running until you stop it.

## Notes

- `netsh wlan connect` requires the target network profile to already exist on the host.
- Windows Location services must allow access to Wi‑Fi scans.
- The standalone scan script in [.test/test-wifi-scan.ps1](.test/test-wifi-scan.ps1) is intended for diagnostics and not for the main application loop.
